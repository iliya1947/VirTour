# PROJECT RULES — VirTour

## 🎯 Product Vision

This project is NOT:

* a demo
* a panorama viewer
* a technical showcase

This project IS:

* a premium real estate marketplace
* with immersive 360 virtual tours
* focused on Israel market

UI quality must feel close to:

* Airbnb
* Zillow
* Booking

---

# 🔥 Core Principles

## 1. UX FIRST

Priority order:

1. UX
2. UI
3. Performance
4. Code

DO NOT generate raw technical-looking pages.

Every page must feel:

* modern
* premium
* commercial
* mobile friendly

---

# 🌍 Localization

Supported languages:

* he (main)
* en
* ru

Hebrew MUST:

* use RTL
* mirror layouts correctly
* feel native for Israeli users

Never hardcode text.

---

# 📱 Mobile First

The product is mobile-first.

All pages MUST:

* work perfectly on mobile
* have proper spacing
* have touch-friendly controls

---

# 🎨 Design Rules

## Style

Use:

* glassmorphism
* smooth transitions
* premium cards
* gradients
* shadows
* large readable typography

Avoid:

* plain white boxes
* raw HTML appearance
* default browser-looking UI

---

# 🧱 Component Architecture

Create reusable components.

Preferred structure:

/components
/layout
/listing
/tour
/ui

Avoid huge page files.

---

# 🧠 Marketplace Rules

The homepage MUST feel like:

* a real estate marketplace
* not a landing page

Listings must include:

* image
* price
* city
* rooms
* badges
* hover effects

---

# 🎥 Tour Experience Rules

Virtual tour pages MUST feel immersive.

Required:

* fullscreen support
* smooth transitions
* overlays
* loading states
* hotspot hints

Avoid:

* raw panorama-only screens

---

# 📞 Conversion Rules

Every property page MUST contain:

* WhatsApp CTA
* call CTA
* agent information

This is critical for Israeli market.

---

# ⚡ Performance Rules

Use:

* lazy loading
* optimized images
* skeleton loaders

Avoid:

* blocking rendering
* oversized images

---

# 🧩 Code Quality

Use:

* TypeScript
* strict typing
* reusable hooks/components

Avoid:

* duplicated UI
* inline giant logic
* monolithic files

---

# 🚫 Forbidden

DO NOT:

* create placeholder-looking UI
* generate unfinished sections
* create demo-looking layouts
* overcomplicate architecture

---

# ✅ Desired Outcome

The project should feel:

* startup-grade
* premium
* investor-ready
* ready for real users

NOT:

* a school project
* a viewer prototype

---

# Emotional UX Rule

The UI must optimize for:

* trust
* aspiration
* premium feel
* emotional engagement

NOT just information display.

Users should feel:
"I want to live there."

NOT:
"This is a software demo."

---

# Localization Integrity Rule

Hardcoded UI strings are forbidden.

ALL visible UI text must:

come from translation dictionaries
support he/en/ru
preserve RTL compatibility

Before finalizing any UI:
verify translation completeness.
